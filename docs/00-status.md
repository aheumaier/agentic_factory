## Cross-cutting facts worth carrying into every diagram

- **There are still two independent trigger paths for `swe-agent`, and
  they now diverge more, not less.** A human manually completes Spec
  Intake (writes `specs/NNN-slug/` via Spec Kit — the official, only
  supported intake flow; the old bespoke `spec/` directory is retired),
  then either:
  (a) a Temporal `AgentPipelineWorkflow` run: Build (E2B sandbox) → Eval-Gate
  → on pass, Register (opens a factory-repo PR); or
  (b) a collaborator comments `@swe-agent build` on a PR, which runs the
  same `agent.py` inside its own E2B sandbox via `.github/workflows/swe-agent-build.yml`,
  authenticated with a scoped GitHub App token — and stops there, with no
  Gate, Register, or Deploy step at all.
  Both paths now run sandboxed (the earlier host-tempdir path is gone); path
  (a) is the only one with a real Gate/Register; path (b) is Build-only. A
  human still reviews and merges the *target*-repo PR outside the factory's
  control either way, and — even on path (a) — also has to somehow trigger
  `RegistryPromotionWaiterWorkflow` and its `pr_merged` signal by hand,
  since nothing does that automatically (see the Orchestration row above).
- **The Braintrust project-name split is fixed.** `harness/swe-agent/agent.py`,
  `harness/template-agent/agent.py`, and `eval/braintrust/eval.config.py`
  all now read the same `BRAINTRUST_PROJECT` env var (default
  `"agent-factory-pilot"`, set in `.env.example`) instead of the setup
  wizard's hardcoded `"My Project"` literal — traces and gate scores land
  in the same project.
- **`eval_gate_passed` can now genuinely be `true`, but only via path (a)
  above, and only for the binary coverage check** (sandbox exit 0 + PR
  opened + at least one `SC-NNN` criterion found in `spec.md`) — it still
  says nothing about whether any criterion's content was actually met. The
  `manifest.yaml` checked into this repo today (`eval_gate_passed: false`)
  predates the automation and was hand-set, not produced by a real run.
- **The LiteLLM bypass is a documented-by-omission deviation**, not a
  stub — the proxy is fully configured and runnable; `swe-agent` simply
  doesn't call it.
- **`spec/` is retired, not missing.** Spec Kit (`specs/NNN-slug/`) is now
  the official Spec/Intake mechanism; the old bespoke `spec/` (schema,
  template, `triage-policy.md`) is a deliberate cleanup candidate, not a
  regression to restore. `tests/test_agent_spec_schema.py` still tests the
  deleted schema and fails unconditionally — delete it rather than fix it.
